# Watermark detector calibration

Measured true-positive and false-positive rates for every Layer-2 watermark
detector, under the transformations images actually meet in the wild. This
document exists because of the project's standing rule (roadmap plan, W2):
**no detector may influence a user-visible verdict until its measured
behavior on held-out data is published here.** A detection claim without a
measured error rate is exactly the overclaiming this tool exists to refuse.

## Detectors

- **`stable-diffusion-invisible-watermark`** (W1, in every CLI/native
  build): decodes the open `invisible-watermark` "dwtDct" scheme used by the
  Stable Diffusion reference pipelines; claims a detection only when a known
  payload (SDXL 48-bit, or SD v1 "StableDiffusionV1" 136-bit) decodes
  **exactly**.
- **`imatag-stable-signature-bzh`** (W2, only when the user passes
  `--watermark-model <ONNX>`): IMATAG's ResNet-18 classifier (MIT), vendor
  decision rule `logits[0] < 0`. Honest coverage limit: it recognizes ONLY
  IMATAG's own bzh-watermarked SDXL-VAE outputs — it is not a general
  Stable Signature detector; its value here is proving the model-detector
  plumbing and this calibration discipline.

## Corpus (held-out, generated by `scripts/gen_calibration_corpus.py`)

100 base photographs — DIV2K validation HR (real photographs, predating
these watermarks, guaranteed clean) — center-cropped to 768×768, in three
sets:

- `clean`: the crops unmodified. Any hit here is a false positive.
- `sd_dwt`: the crops with the SDXL 48-bit payload embedded by the
  **verbatim reference embedder** (same vendored ShieldMnt code the test
  vectors use), so TPR is measured against ground truth our decoder did not
  produce.
- `bzh`: the crops passed encode→decode through IMATAG's published
  bzh-watermarked SDXL VAE (`imatag/stable-signature-bzh-sdxl-vae-medium`).
  Honest asymmetry: real bzh deployments watermark SDXL *generations*;
  VAE-roundtripped photographs are a proxy for "this VAE touched the
  pixels", which is precisely what the classifier is trained on.

Each set member appears under eight variants: `orig`, JPEG re-encode at
quality 90/70/50, bicubic resize to 75%/50% per side, central 80% crop, and
`screenshot` (bicubic resize to 110% then JPEG q85 — a cheap simulation of
render-and-recapture).

Hits on a detector's own watermarked set are true positives; hits on
`clean` — and on the *other* scheme's set — are false positives.

Reproduce: generate the corpus with the script above (needs numpy, opencv,
PyWavelets, torch CPU, diffusers), export the bzh model with
`scripts/export_stable_signature_onnx.py`, then run the exact production
probes:

    cargo run --release -p provenance-core --features stable-signature \
        --example calibrate -- <corpus-root> --model <bzh.onnx>

## Large-corpus clean FPR

`measure_fpr` over the flat clean corpora (no transformations):

- `stable-diffusion-invisible-watermark`: **0 / 2,861** (2,800 DIV2K
  images — train+valid HR plus the official bicubic LR packs — and the
  maintainer's 61-photo local library). 0.0000%.
- `imatag-stable-signature-bzh`: **0 / 2,800** (the same DIV2K corpus;
  the vendor's card states ~1/1000 — we measured better than that here).

Combined with the transformed `clean` sets above (800 variants each,
0 hits), no false positive has been observed from either detector on any
corpus this project has measured.

## Reading the numbers honestly

- **The DWT watermark is fragile, and now that's measured, not folklore**:
  45% of reference-embedded pristine PNGs decode fully, and a single JPEG
  re-encode at quality 90 — or any resize, crop, or screenshot — drops
  detection to 0%. That is the scheme's property (the SD community's own
  experience says the same), not a detector bug: the exact-payload rule
  reads only unmutilated survivors. What the detector buys, per these
  tables, is certainty in the positive direction: not one invented
  detection across every clean corpus and transform measured.
- **The bzh classifier is the sturdier detector** (30–85% TPR across the
  battery, still 0 measured false positives). Two honest caveats. First,
  our watermarked set is VAE-roundtripped *photographs* — a proxy; real
  bzh deployments watermark SDXL *generations*, where the vendor's own
  numbers are presumably higher. Second, the curious crop80 result (85%,
  above orig's 51%) is consistent with the 512×512 model input: cropping
  768→614 means less downscaling into the model than 768→512, so more
  watermark energy survives preprocessing — detection strength depends on
  how far the input is from the model's native scale.
- With zero observed false positives at these sample sizes, a hit from
  either detector is strong (though still non-cryptographic) evidence —
  hence `Indicated`, never `Verified`. A miss means **nothing**: a
  watermark that fails to survive a transformation yields `Inconclusive`,
  never "authentic". That founding rule is what makes shipping
  fragile-but-honest detectors acceptable.
- The bzh classifier's numbers apply to IMATAG's bzh watermark only.
  Nothing here measures — or claims — detection of SynthID or any scheme
  without a public decoder.
